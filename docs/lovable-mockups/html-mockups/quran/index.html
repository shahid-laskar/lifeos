High-fidelity mockups for the complete Qur'an module: surah list, reader, translation, tafsir, audio, bookmarks, hifdh and reading insights, across mobile 390, tablet 834 and desktop 1440, in light and dark, with loading, empty, populated and error states. 1. Surah list

Entry point for the whole module. The Continue Reading banner reuses the dashboard hero exactly — same 20px radius, same 7% khatam texture, same white 100/75/62% opacity tiers — so resuming a recitation feels like the same object as the prayer banner rather than a new component. Surah numbers sit in an emerald hexagon rather than a circle: circles are already spoken for by prayer status on the dashboard, and the hexagon echoes the geometry of the star texture. Progress is a hairline bar on read surahs and a small check on completed ones, never a percentage badge or streak. Search and filters are hairline-bordered, not filled, matching Linear-style chrome restraint.

2. Reader — the digital Mushaf

The single deliberate departure from the dashboard's card grid, and the reason for it: on every other screen the card is the object, but here the page is the object. Wrapping revelation in a bordered card would frame it as one widget among many. So the reader drops to bare surface with a 640px measure, and cards return only for metadata and error states. Everything else is inherited — hairline dividers between ayahs instead of shadows, 12px/0.12em micro-labels, the same emerald. Ayah numbers are outlined circles in the margin at 26px, never inline in the Arabic run, because an inline glyph forces the eye to break the naskh line. Arabic is Amiri at 29-31px on 1.9 line-height (the plan's 24-48px range starts comfortably mid-scale); translation is Lora one weight and one colour step down with a hairline left rule, so it reads as a second, quieter voice rather than a competing column. Bismillah is centred between two hairline rules and is omitted for At-Tawbah. Reading progress is a 2px emerald line under the header — the only always-visible progress indicator, driven by IntersectionObserver per §3D, never a percentage counter that would turn recitation into a score. The currently recited ayah is tinted primary-soft, the same tint the dashboard uses for its reflection prompt.

3. Immersive reading mode

Everything except the ayahs is removed: no header, no tab bar, no sidebar, no audio strip, no ayah tools. Arabic steps up to 34px on 2.05 line-height and vertical padding roughly doubles, so the page breathes the way a printed Mushaf does. The exit control is a single ghost icon top-right at 36px, held in the active emerald state so it never reads as decoration, and one 11px/0.1em uppercase hint sits at the bottom — the same micro-label style used for card headings, so the hint is legible as system voice rather than as content. Warm parchment and green-black grounds are unchanged, because inverting or dimming the theme in immersive mode would break the promise that dark mode is night rather than a reading filter. No page-turn animation, no parallax: motion stays at the dashboard's budget of skeleton pulse and nothing else.

4. Tafsir panel

Tafsir has to read as a scholarly annotation, not another card. So it gets its own treatment: the passage body sits on the page ground (--bg, one step behind --surface) with a 2px emerald left rule and an asymmetric radius — square on the ruled edge, 14px on the other three — which is the visual grammar of a marginal gloss. Lora at 14.5px/1.78 keeps it in the same voice as translation and hadith. The cited ayah is repeated in Amiri at the top so the panel is self-contained when it covers the reader. Source attribution appears twice on purpose: the mufassir before the text, the edition and abridgement note after it, because unattributed tafsir is a trust failure in an Islamic app. Multiple tafsirs are a three-up segmented control rather than a dropdown, so switching costs one tap and the available scholarship is visible. On mobile it is a bottom sheet at 22px top radius with a grab handle; at desktop it becomes a 340px right rail with a hairline left border — the reader never reflows its measure when the rail opens, so the eye keeps its place.

5. Audio player

Recitation is listening, not media consumption, so nothing here borrows from music-player language: no album art, no bouncing waveform, no scrubbing thumbnail. The mini bar is a hairline-topped strip on the surface colour, pinned above the tab bar at desktop and mobile alike, carrying qari, exact reference and tabular elapsed time. Expanded, the sheet leads with the qari — attribution before controls — using an Amiri initial in a primary-soft tile rather than a photograph, since photographs of reciters are inconsistent and often inappropriate to crop. The three toggles are the ones that actually matter for recitation practice: follow-along scroll, ayah repeat, and continue-to-next-surah, each with a plain-language sub-line. Position is a hairline track with a 22px hollow handle, and remaining time is negative-prefixed so the eye reads what's left rather than doing arithmetic. 8. Bookmarks

A bookmark's job is to bring back the moment, so each row leads with the reference in emerald tabular figures, then the Arabic at 22px, then translation, then any private note. The note sits in a primary-soft block — the same tint as the dashboard's reflection prompt, because both are the user's own voice reflected back. Rows live inside one shared hairline-divided container rather than separate cards: twelve floating cards would read as a feed, which is exactly the social-media pattern to avoid. There is no like count, no share count, no public anything. The empty state names the gesture that creates a bookmark and offers one surah, since 'long press to save' is invisible until someone says it. The desktop sync-failure card is the only place an error appears without blocking reading, and it says the data is safe before it asks for a retry.

9. Hifdh tracker

This is where brass earns its keep. On the dashboard brass appears exactly once, for khushoo; here it carries memorisation confidence, which is the same kind of quantity — an honest self-assessment that shouldn't be dressed as achievement. New sits at 45% brass opacity, steady at full brass, strong graduates to emerald, and every level carries a word as well as a colour, so the state survives colour blindness and greyscale. The grid shows all 114 surahs (the audit's .slice(0,10) bug becomes a design requirement) as 84px cells with a 4px bar, dense enough to scan like a contribution grid without ever becoming one: no counts, no intensity heat, no streak. Review scheduling is stated in days and minutes, and the 'Review kept' card deliberately says 'No streak counted' so the absence is visible rather than felt as a missing feature.

10. Reading insights

Modelled on Apple Health's modularity: one card, one metric, stated as a sentence before any number is shown — the direct answer to the audit's complaint that '12 / 30 days is data but not insight'. Nothing here can be won. Pace reports that a khatam would take about fourteen months and then says plainly that no target has been set, because inferring a goal the user never chose is how habit apps start nagging. Coverage reuses the dashboard's conic ring at the same 74px with the same 7px inner cut, so the shape already means 'a whole against its part' by the time it appears here. The 'Returning' card is the emotional centre: it shows the ayah, in Arabic, that the person keeps coming back to, which is a form of insight only a Qur'an app can offer. Charts are hairline bars and the seven-day strip already established on the dashboard — no line charts, no axes, no tooltips.
